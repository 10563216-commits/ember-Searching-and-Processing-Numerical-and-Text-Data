# ember — Lab 05: багато однакового

Екран 64 × 32 у `ember` — це не окремий масив, а **256 байтів тієї самої пам'яті** на адресах `0xA00 … 0xAFF`, по одному біту на піксель. Рівень: Standard, плюс порт виводу з розділу «Якщо встигаєте» і `sort`.

## Збірка й запуск

```
make            # build/ember
make test       # 29 перевірок: екран, OUTS, UTF-8, find, sort, асемблер
make asan       # те саме з ASan/UBSan (build/ember-asan)

./build/ember                       # інтерактивно, команда help
./build/ember [-q] скрипт.ember     # виконати команди зі скрипта (-q — без луни команд)
```

Потрібен компілятор з C++17. Файли в `examples/` — програми для `asm`.

## Формула «байт і біт»

```
адреса байта = 0xA00 + y * 8 + (x / 8)    ; 64 пікселі / 8 бітів = 8 байтів на рядок
номер біта   = 7 - (x % 8)                ; біт 7 — найлівіший піксель байта
горить       = (mem[адреса байта] >> номер біта) & 1

plot:   mem[адреса] |=  (1u << номер)
unplot: mem[адреса] &= ~(1u << номер)
```

`y * 8` — крок рядка, `x / 8` — який байт у рядку, `x % 8` — який біт у байті, а `7 -` стоїть тому, що пишемо зліва направо, а біти нумеруємо справа наліво. Приклад: піксель (13, 2) лежить у байті `0xA00 + 2*8 + 1 = 0xA11`, біт `7 - 5 = 2`.

Бітова упаковка коштує 64 × 32 / 8 = **256 байтів**. Байт на піксель було б 2048, тобто половина всієї пам'яті машини.

### Піксель без `PLOT`

`examples/pixel_no_plot.asm`: `CLS`, `LOADI A, 0x80`, `LOADH H, 0x0A00`, `STORE [H], A`, `SHOW`. У лівому верхньому куті світиться один піксель, `dump 0xA00 8` показує `80 00 00 00 00 00 00 00`. Карта пам'яті, порядок бітів і `show` узгоджені.

### Три пікселі через `PLOT`

`examples/three_pixels.asm` ставить (1,1), (2,2), (3,3): це байти `0xA08 = 40`, `0xA10 = 20`, `0xA18 = 10`.

## UTF-8

Нічого не перекодовується: байти йдуть у пам'ять і з пам'яті як є, а термінал збирає їх у літери. З цього випливає кілька речей.

- **Байти ≠ символи.** Українська літера — 2 байти, `—` — 3, смайлик — 4. `str 0x800` показує обидва числа: `"Привіт, світе! Їжак і Єнот — друзі 🙂\n"` займає 67 байтів і 37 символів.
- **Стеля не ріже літеру.** `OUTS` зупиняється на `'\0'` або на 256 байтах. Якщо стеля падає посеред символу (256 не ділиться на 3), недописаний хвіст відкидається, інакше термінал отримав би зламану послідовність. Перевірено: `fill 0x800 0xA00 E2 80 94` дає рівно 85 цілих `—` і коректний UTF-8.
- **Вхідні файли.** Асемблер знімає BOM (Блокнот Windows) і CRLF, а рядок `.str`, що не є коректним UTF-8, дає попередження (типовий випадок: файл збережено в cp1251).
- **Консоль Windows.** `main` викликає `SetConsoleOutputCP(CP_UTF8)` і `SetConsoleCP(CP_UTF8)`. На Linux і macOS нічого робити не треба, якщо локаль UTF-8.
- **Екран.** `style block` малює `█` і `·` замість `#` і `.` (літерали записано шістнадцятковими байтами, тож результат не залежить від кодування вихідного файлу).
- **Сирий байт у `OUT`.** `OUT` друкує один байт, тому багатобайтовий символ виходить лише з кількох `OUT` поспіль.
- Якщо збираєте MSVC, додайте `/utf-8`: у вихідних файлах є українські повідомлення.

## Команди REPL

`help` друкує повний список. Коротко: `dump`, `get`, `set`, `load` (шістнадцяткові байти), `puts addr "текст"` (UTF-8 + `'\0'`), `str`, `fill`, `asm файл`, `run`, `step`, `regs`, `reset`, `wipe`, `show`, `cls`, `frame`, `plot`, `unplot`, `style`, `find`, `sort`.
